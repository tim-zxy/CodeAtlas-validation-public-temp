# Historical reader/native tool preflight

Prepared only, not run or published. This separate manual workflow compares the original public retained-Native and reader environment (image and eight tool-byte hashes), not current product source qualification. It neither modifies nor replaces old preflight/guard files. Expected data is selected from public asset757432131, whose GitHub digest matches the locally checked archive; reader/original-Native image, compiler versions and tool entries agree. The embedded origin pins archive/member digest and original source IDs. No physical catalog, paths, logs, source project, SQLite or executable is copied.

One standard windows-2025 job,5minutes; manual dispatch only, first attempt only, no cancellation of existing runs. Zero token permissions, no checkout/actions, dependency install, downloads, direct script file writes, build, source reads or artifact/release upload. It uses the runner's existing default Node to execute an inline stdlib script. That bootstrap is not guaranteed on an unobserved runner; missing Node fails the job without installation. Runtime only resolves paths with original where.exe/rustup which/vswhere rules and hashes node, PowerShell, tar, cargo, rustc, cl, linker and rc; it does not execute compilers or Native. Resolver commands retain10/15-second timeout and10KB capture limits. A timed-out/unconfirmed child stops later resolution and reports UNKNOWN. This covers queried resolvers only, not a process-tree isolation or historical cleanup proof.

Only structured JSON is emitted: fixed schema/scope/origin, constrained numeric image versions, eight role/status/hash/matches rows, resolverCleanup, allMatch and permanent eligibleForNativeReuse=false/qualification=NOT_ATTEMPTED/nativeExecuted=false. Native command stderr and resolved physical paths are captured/discarded and never printed. Malformed ImageVersion is null. A mismatch or unavailable tool exits1; there is no retry or downstream build/qualification job. Matching exit0 only supports a later original-guard check; it cannot qualify a source revision, adopt a reservation or authorize reuse. The standard GitHub runner platform still controls its own system logs; this script does not claim log privacy or hard isolation outside its output.

The synthetic Node tests extract/load only this reviewed inline module with main disabled by require semantics, and inject fake resolution/hash functions. They never invoke actual tool probes. Public publication requires a reviewed single-parent commit based on current public main6172bbf0, explicit branch push, and normal platform approval; future dispatch must name that exact control SHA. The repository has one push workflow, restricted to clock-unit-* branches; this maintenance branch/main do not match. Future workflow_dispatch requires this new workflow to be registered on default main first (https://docs.github.com/actions/using-workflows/workflow-syntax-for-github-actions#onworkflow_dispatch). Only the three reviewed new files should be registered, not unrelated qualification branches. No other workflows are changed or automatically run by these files. No artifact is uploaded; standard Actions logs use repository retention settings, which were not read or changed.

Rustup auto-install is explicitly disabled in each query child's environment, tracing is removed only from that child, and an already-present Rustup home/settings file is required before invoking which. Missing metadata refuses instead of bootstrapping or repairing it. No persistent environment/settings are changed; the script's direct filesystem operations remain stat/read only. This uses the official per-invocation RUSTUP_AUTO_INSTALL=0 behavior (https://rust-lang.github.io/rustup/environment-variables.html), without changing installed-path selection or the original reuse guard. External resolvers still run within the trusted hosted environment; no OS sandbox or universal no-side-effect guarantee is claimed.

Local preparation evidence: `node --test native-reader-tool-preflight.test.mjs` runs only synthetic comparison/resolution helpers, not actual probes. YAML semantics and scoped formatting are checked separately with already available tools; no package is installed for validation.
